# Patches to upstream Firefox

Base: Firefox ESR **153.7.0** (`FIREFOX_153_7_0esr_RELEASE`,
`github.com/mozilla-firefox/firefox`).

Skein keeps its diff against Firefox as small as possible so rebasing onto new
ESR point releases stays cheap. Almost everything is **new files** in an
overlay tree; only the edits below touch upstream files.

## Overlay (new files, copied by `scripts/apply.sh`)

| Path in the Firefox tree | What |
|---|---|
| `browser/components/skein/` | Skein's own code: validator, customization engine, spaces, privacy mode, `about:skein`, agent docs generator, stable surface table. |
| `browser/branding/skein/` | Branding directory generated by `scripts/make-branding.sh` from Firefox's trademark-free `unofficial` branding plus Skein's name, icons and default preferences. |

The component hooks into browser windows through the category manager
(`browser-first-window-ready`, `browser-window-delayed-startup`,
`browser-window-unload` in `skein.manifest`), which is why no patch to
`browser-init.js` or `browser.xhtml` is needed.

## Patches (edits to upstream files, in `patches/`)

| Patch | Files | Why |
|---|---|---|
| `0001-register-skein-component.patch` | `browser/components/moz.build` | Adds the `skein` directory to the build. One line. |
| `0002-about-skein.patch` | `browser/components/about/AboutRedirector.cpp`, `components.conf` | Registers `about:skein` (parent-process chrome page). About pages are a static C++ table, so this cannot be done from the overlay. Also points `about:rights` at the bundled open-source licences page instead of Mozilla's Firefox terms of use, which do not apply to Skein. |
| `0003-space-container-for-new-tabs.patch` | `browser/base/content/browser-commands.js` | When the active space is bound to a container, the New Tab command opens the tab in that container. Hooked at the command (not `addTab`) so session restore and links are unaffected. |
| `0004-vendor-and-normandy.patch` | `browser/moz.configure` | `MOZ_APP_VENDOR` "Mozilla" -> "Skein" (profile location, no Mozilla naming); `MOZ_NORMANDY` off (no remote studies/experiments client in the build). `MOZ_APP_ID` is deliberately unchanged so add-ons that target Firefox install. |

`scripts/apply.sh` also replaces the hard-coded product name in
`browser/locales/en-US/chrome/overrides/appstrings.properties` (network error
page strings) with "Skein", and renames the "Firefox Suggest" address bar group
label to "Suggestions" in `toolkit/locales/en-US/toolkit/branding/brandings.ftl`.
Both are a `sed`, not a patch file, so they survive
upstream wording changes.

## Build configuration (not patches)

`mozconfigs/common.mozconfig`: `--with-app-name=skein`,
`--with-app-basename=Skein`, `--with-branding=browser/branding/skein`,
`--disable-crashreporter`, `--disable-updater`.

## Rebasing onto a new ESR release

1. `git -C engine fetch --depth 1 origin tag FIREFOX_<version>esr_RELEASE` and check it out (after `git stash`/reset of the patched files).
2. `scripts/apply.sh`. A patch that no longer applies stops the script; fix it
   by hand, re-export with `git -C engine diff -- <files> > patches/<name>.patch`.
3. `node scripts/check-stable-surface.mjs` must pass. If a token or region
   went missing, map it to its new name in `SkeinSurface.sys.mjs`.
4. Regenerate branding (`scripts/make-branding.sh`), build, run
   `node --test skein/tests/validator/` and `python3 scripts/dev/test_skein.py`.
5. Update the base version at the top of this file and in `SkeinSurface.sys.mjs`.
