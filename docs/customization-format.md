# Skein customization folder format (v1)

This is the contract between Skein and any local agent (Claude Code or
otherwise). It is agent-agnostic: an agent only needs to edit files.

The folder lives **outside** the browser profile:

| OS | Path |
|---|---|
| Linux | `~/.config/skein-customization/custom/` |
| Windows | `%APPDATA%\SkeinCustomization\custom\` |
| macOS | `~/Library/Application Support/SkeinCustomization/custom/` |

Override with the `skein.customization.dir` preference. Skein treats everything
in this folder as untrusted input and validates it on every load. Never put
secrets here.

## Layout

```
custom/
  skein.json                 which skills are enabled (the only required file)
  SKILL.md                   instructions for agents (generated by Skein; ignored on load)
  skills/
    <skill-id>/
      skill.json             metadata + what the skill touches
      chrome.css             styles for the browser interface      (touches: css)
      layout.json            structured layout choices             (touches: layout)
      prefs.json             allowlisted interface preferences     (touches: prefs)
      keybindings.json       shortcuts for Skein commands          (touches: keybindings)
      assets/                images / woff2 fonts used by chrome.css
      README.md              optional, ignored
```

Skein also keeps `custom/../state/snapshots/` (outside this folder) with a copy of
every bundle it applied. Agents never need to touch it.

### skein.json

```json
{
  "formatVersion": 1,
  "enabled": ["midnight", "tabs-right"],
  "spaces": {
    "Work": { "enabled": ["calm"] }
  }
}
```

`enabled` skills apply everywhere, in order (later skills win). `spaces.<name>.enabled`
skills are layered on top while that space is active.

### skill.json

```json
{
  "id": "midnight",
  "name": "Midnight",
  "description": "Dark violet theme",
  "author": "you",
  "version": "1.0.0",
  "touches": ["css", "layout"]
}
```

- `id` must equal the folder name: lowercase letters, digits, hyphens, max 48 chars.
- `touches` must list exactly the files the skill ships. A file that is present
  but undeclared (or declared but missing) fails validation.

### layout.json

```json
{
  "tabs":    { "orientation": "vertical", "side": "right", "expanded": true },
  "toolbar": { "position": "bottom", "bookmarksBar": "never" },
  "density": "compact",
  "spaces":  { "showLabels": true }
}
```

Every key is optional. Use this, not CSS, to move regions around: it is stable
across Firefox updates and cannot hide security UI.

### prefs.json

```json
{ "prefs": { "browser.uidensity": 1, "skein.focus.compact": true } }
```

Only interface preferences on the allowlist in `SkeinValidator.sys.mjs`
(`ALLOWED_PREFS`) are accepted. Network, security, privacy, extension, update
and devtools preferences are never settable from a skill. When a skill is
disabled or rolled back, Skein restores the previous value.

Skein's own interface switches, all settable from a skill:

| Preference | Values | Default | What it does |
|---|---|---|---|
| `skein.ui.zen` | true / false | true | Zen-style layout (sidebar, floating page card) |
| `skein.ui.topSearchBar` | true / false | false | Put the address bar back in a classic top toolbar |
| `skein.ui.sidebarUrlbar` | true / false | false | Show a quiet address line (padlock + site) in the sidebar |
| `skein.ui.topBar` | true / false | true | Hover top bar with the window buttons (minimize, maximize, close) |
| `skein.ui.tabCloseButton` | `"hover"` / `"always"` / `"never"` | `"hover"` | When the tab close button (right side) shows |
| `skein.focus.compact` | true / false | false | Compact mode: sidebar slides away, returns at the left edge |
| `skein.focus.sidebarHidden` | true / false | false | Hide only the sidebar; it glides back when the pointer reaches its edge. In the Zen layout, `layout.tabs.expanded: false` turns on compact mode, and Firefox's own `expand-on-hover` is switched off because it fights Skein's hover |
| `skein.focus.floatingNewTab` | true / false | true | New tab floats the address bar instead of opening a page |
| `skein.glance.altClick` | true / false | true | Alt+click a link opens it in Glance |
| `skein.spaces.showLabels` | true / false | false | Show every space's full name in the switcher |

### keybindings.json

```json
{ "bindings": [ { "command": "skein:next-space", "key": "]", "modifiers": ["accel", "alt"] } ] }
```

Commands: `skein:next-space`, `skein:previous-space`, `skein:new-space`,
`skein:space-1` … `skein:space-9`, `skein:toggle-vertical-tabs`,
`skein:toggle-sidebar`, `skein:open-settings`, `skein:rollback`.
A binding needs at least one of `accel`, `alt`, `control`, `meta` (function keys excepted).

### chrome.css

Applies to the browser window only, never to web pages, never in Privacy mode
or private windows. Rules, enforced by the validator (it fails closed):

1. **No remote loads.** `url()` may be `data:image/*`, a `chrome://browser|global|branding`
   image, or `assets/<file>` inside the skill. No `@import`, `image-set()`, `-moz-element()`.
2. **No backslash escapes, no nested rules.** Allowed at-rules: `@media`,
   `@supports`, `@keyframes`, `@font-face`, `@layer`, `@container`.
3. **Security UI is restyle-only.** Any selector that names an id, class or tag
   starting with `urlbar`, `identity-`, `tracking-protection`, `trust-icon`,
   `permission`, `popup-notification`, `notification-popup`, `protections-popup`,
   `downloads`, `dialog`, `fullscreen-warning` or `pointerlock` (plus a list of
   exact names in `SkeinValidator.sys.mjs`) may only set opaque literal `color`,
   `background-color`, `border-color`, `outline-color`, `caret-color`,
   `border-*-radius`, `font-family`, `font-weight`. Attribute selectors on
   `id`/`class` count as naming them.
4. **Containers of security UI** (`#nav-bar`, `#navigator-toolbox`, `#urlbar-container`,
   `#browser`, `:root`, …) can be restyled but not hidden, shrunk, clipped or repositioned.
5. **Hiding/positioning properties** (`display`, `visibility`, `opacity`, `transform`,
   `position`, sizes, margins, …) need a selector whose last part names an id or
   class. `* { display: none }` style rules are rejected. Keyframes may not animate them.
6. Generated `content` is not allowed on security UI or its containers.
7. **Custom properties.** Only Skein's tokens (`--skein-*`, listed in the
   generated `SKILL.md`) and private `--my-*` variables may be declared. The
   browser's own variables cannot be overridden: several of them size or colour
   security UI. Background/text token pairs (chrome, toolbar, field, sidebar,
   panel) must be set together as literal colours with a contrast ratio of at
   least 3, because panels and prompts are not on screen when the runtime
   check runs.

After applying, Skein runs a **runtime integrity check** on the live window,
comparing it with the same window without the skill stylesheet:

- the toolbar, address bar, site identity and tracking-protection icons are
  still displayed, on screen, opaque and not covered (hit-testing is forced on
  for every box, so `pointer-events: none` overlays are found);
- nothing is painted over the web page (a 5 x 5 grid of points must hit the
  page itself);
- the address bar text is still distinguishable from the pixels actually
  rendered behind it.

If it fails, the change is rolled back automatically and the reason is shown in
`about:skein` and `.status.json`. Known limits: the check runs when a bundle is
applied and when a window opens or switches space, not continuously, so it does
not see states that only exist while hovering or while a panel is open.

## Apply cycle

1. Skein notices a change in the folder (polling, about once a second).
2. It reads the folder (regular files only; symlinks are refused) and validates it.
3. Invalid: nothing changes; errors with file and line appear in `about:skein`
   and in `custom/.status.json` (written by Skein, ignored on load) so the agent can read them.
4. Valid: Skein snapshots the bundle, applies it live (no restart), runs the
   integrity check, and records the result.
5. `about:skein` shows the diff against the previous snapshot and offers
   one-click rollback. Safe mode (`skein --safe-mode`, or the toggle in
   `about:skein`) starts with every skill disabled.

## Where things live (Linux)

| What | Path | Who writes it |
|---|---|---|
| Customization folder | `~/.config/skein-customization/custom/` | your agent |
| Snapshots and Skein's state | `~/.config/skein-customization/state/` | Skein only |
| Browser profile (history, cookies, logins) | `~/.config/skein/skein/` (or `~/.skein/skein/` on systems with a legacy `~/.mozilla`) | Skein only; never give an agent access |
